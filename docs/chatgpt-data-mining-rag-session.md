## 맥락 레이블 정리

### A — Entity-Centric Knowledge Object
**의미 + 관계 + 시간/상황 맥락 + 근거**를 함께 담는 개체 중심 지식 표현.
- 의미 축: "이 개체가 무엇인가" (속성, 설명, 상태)
- 관계 축: "이 개체가 무엇과 연결되는가" (사람, 사건, 조직, 원인, 결과)
- 단순 문서 chunk보다 크고, 그래프의 빈 노드보다 풍부한 단위

### B — Stateful/Verifiable Knowledge
지식은 **시간 순서 + 무결성 + 정합성 + 상태 전이 검증 가능성**을 통해 형성됨.
- 정보 단순 집합이 아니라 시간 속에서 검증되며 누적된 구조
- 관계도 정적 엣지가 아니라 시간성과 상태를 가진 관계
- 블록체인은 이 원리의 극단적 제도화

### C — 언어 = A+B의 외부화 인터페이스
사람이 세상을 이해하는 최소 단위 = 의미 + 관계. 이것이 조합되면 말과 글.
- 사업계획서, 코딩, 연구는 표면 형식만 다른 동일 구조 (개체 정의 + 관계 구조화)
- 사업/코딩/연구를 모두 잘하는 사람 = A+B를 잘 다루고 언어로 잘 표현하는 사람
- LLM = 인간의 지식 구조화 흔적(A+B)을 언어 차원에서 압축·재조합하는 엔진

### D — Gemma = 선택기(Selector)
**Gemma에게 요구하는 것은 "이해"가 아니라 저토큰 고반복 병렬 선택**.
- Gemma 역할: selector / router / scorer / sampler
- A/B/C 구조의 지식 공간에서 빠르게 반복적으로 관련 노드 선택
- 생성 모델이 아니라 selection model처럼 사용
- 사람이 이해의 주체, 지식 구조(A/B/C) 설계도 사람

### E — 중력 기반 응집 + 강화학습
**목표 중심 지식 중력장**: 정보들 사이의 끌림 강도.
- 목표가 생기면 각 정보 노드는 다른 중력값을 가짐 (중심/주변/무관)
- 중력 = 관련성 + 관계성 + 최신성 + 검증성 + 출력 목적 적합성 + 반복 선택 안정성
- 강화학습과 자연스럽게 연결: Gemma의 반복 선택이 policy, reward는 지식 정합성 지표

### F — LangGraph = 선택과 전이를 조직하는 언어
- 인간 언어: 의미를 담는 언어
- LLM 내부: 토큰 + 잠재표현 계산 구조
- LangGraph: LLM이 A/B/D/E 방식으로 움직이게 하는 행동 조직 언어 (상태 전이 언어)

## G — 지식 항성 모델 (핵심 결론)

### 정의
블록체인적 최소 정보 단위들을 목표 중심의 지식 중력장 안에서 반복 선택·응집시키고,
A와 B의 안정화 힘으로 구조를 유지하다가, 연결 임계값을 넘는 순간 창발된 새 지식을
폭발적으로 재분산·재분할하여 다시 다음 지식 구조의 재료로 환원하는 **순환형 지식 생성 모델**.

지식은 정적 저장물이 아니라:
분해 → 선택 → 응집 → 안정화 → 창발 → 폭발 → 재분해 하는 **순환적 구조체**

### 핵심 구성요소

**정보 노드** (최소 단위)
- 블록체인적 속성: 사실/개체/관계/이벤트/상태/상태변화/근거/버전
- 언제 생성 / 무엇과 연결 / 어떤 근거 / 어떤 상태 전이를 거쳤는지 포함
- 안정 상태: 연결선 최대 3개

**지식 중력장**
- 목표 주어지면 그 목표 중심으로 형성
- 각 정보 노드는 동일한 힘이 아니라 다른 중력값 보유
- 중력 = 목적에서 그 정보가 끌려와야 할 이유의 총합

**지식 항성**
- 정보 노드들이 중력장 안에서 응집한 안정 구조
- A(의미·관계·맥락·근거 구조 안정화) + B(시간·무결성·검증 구조 안정화)가 붕괴 방지

**3연결 vs 4연결 임계**
- 3연결까지: 안정된 최소 단위 유지
- 4번째 연결 생성 = 창발(Emergence) 신호
  - 단순 복잡도 초과가 아니라 **새로운 지식/사실/관계가 생성됨**을 의미
  - 기존 원자 정보들의 응집으로 기존에 없던 상위 패턴 등장

**폭발(초신성) = 재구성 가능한 분해**
- 4연결로 창발된 새 지식을 다시 최소 단위로 풀어내는 과정
- 파괴가 아니라 생성된 고차 지식의 재분산
- 재분산된 조각이 다음 지식 항성의 재료

### 시스템 2축 구조

**G축 (지식 형성)**
```
정보 노드 → 중력 응집 → 지식 항성 → 창발 → 재분해
```

**P축 (문서화)**
```
지식 항성 → 평면 투영 → 문서 구조화 → 문장화 → 검증
```

### 하드웨어 역할 분리

| 장치 | 역할 | 특성 |
|------|------|------|
| 맥북 Gemma e4b | 선택기 | 저토큰, 고반복, 병렬 탐색, 노드 선택, 중심성 형성 |
| 4090 Gemma a4b | 투영기 | 응집된 G 입력 수신 → 문서 스키마에 맞게 투영 → 섹션별 전개 |

- 4090은 "없는 정보 창조"가 아니라 "응집된 지식 항성을 문서 평면으로 펼치기"
- 탐색+응집+생성 동시 처리 → 응집된 결과를 전개하는 문제로 난이도 격하
- 환각 위험 감소: 지식 항성이 이미 중심 주장/근거/최신 상태를 보유

### 뭉침 단계 (비LLM vs LLM)

| 단계 | 방법 | 예시 |
|------|------|------|
| 1차 기계적 뭉침 | 비LLM 가능 | 벡터 유사도, 그래프 탐색, 규칙 기반, 태그/메타데이터 군집화 |
| 2차 의미적 뭉침 | 경량 LLM | "표면 단어는 다른데 같은 문제", "이 자료들은 사업계획서상 한 덩어리" |
| 3차 목적 지향 뭉침 | LLM + 투영 규칙 | 사업계획서/코드/연구별 뭉침 기준 다름 |

LLM은 경계 판정(이 노드가 이 항성에 들어가야 하나?)에만 사용 → 효율적

### 사이클 예측

| 작업 규모 | 노드 수 | 예상 cycle |
|-----------|---------|------------|
| 한 섹션/주장 | 20~80 | 3~8 |
| 사업계획서 한 절 | 80~300 | 8~20 |
| 사업계획서 전체 | 300~1500+ | 20~60+ |

→ 문서 전체를 한 번에 뭉치지 말고 절/섹션/주제 단위 지식 항성으로 나눠야 함

## 출발점과 목적

- **출발점**: Gemma 4 e4b 4-bit 기반 사업계획서 작성 품질 불만족
- **문제 원인**: 작은 양자화 모델의 장거리 일관성 유지, 근거 결속, 수치-논리 정합성 약함
- **해결 방향**: 모델을 더 크게 기대하는 게 아니라, 모델이 다룰 지식 단위와 작성 프로세스 변경
- **결론**: G(지식 항성) 구축 + P(투영 하네스) 설계 = 완전 새 구축
